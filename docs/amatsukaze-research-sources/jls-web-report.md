# 0. コミュニティで共有されているアーキテクチャ認識（前提）

**事実**
- join_logo_scp (JLS) のREADMEは「事前に別ソフトで検出した『ロゴ表示区間』『無音＆シーンチェンジ』の情報を基にして、CMカット情報(Trim)を記載したAVSファイルを作成する」と明記し、前者に logoframe、後者に chapter_exe（改造版 by Yobi を推奨: 「オリジナルでも一応可能と思いますが、改造版を使った方が明確に違いがわかるレベルで精度が上がります」）を指定する。出典: https://github.com/yobibi/join_logo_scp
- 同READMEは「ロゴ結果なしでも精度は多少落ちますが動作可能にしました（ver2.1追加）」と明記。出典: 同上
- カット処理方法は「JLスクリプト」（JL_標準.txt等）で記述され、「３０分枠アニメのCMカットでチューニングしてありますが汎用的に使えると思います」（同README、JL_標準.txtについて）。
- Amatsukazeスレ（5ch その8 レス900）での要約: 「join_logo_scpは別ソフトの検出結果（ロゴ区間と無音シーンチェンジ位置）をテキストファイルで読み込んでCM区間を判断している」。出典: https://mevius.5ch.net/test/read.cgi/avi/1752302318/
- 「CMカットは独立スレがあるくらい奥が深い」という利用者の感想（その8 レス53）。出典: 同上
- CMカット専用スレ（5ch「CMカット スレ」シリーズ）が存在し、JLSの更新情報は「5chのCMカットスレ」で配布・告知されてきた経緯がある（オタクの徒然日記: 「join_logo_scp.exeの更新頻度が上がっているので最新版をすぐ入手したい方は5chのCMカットスレ★3を見に行ってみて下さい」）。出典: http://blog.livedoor.jp/fles/archives/76744385.html
- 最新のJLS v5.1.1（2026年6月リリース）の修正内容に「15秒単位からの差認識が正常にできていなかった所を修正」が含まれる。出典: https://github.com/yobibi/join_logo_scp/releases/

**示唆（依頼者への含意）**
- 依頼者のパイプライン（1デコードで特徴抽出→区間推定→ルールベース確定）は、JLS系コミュニティの「検出（logoframe/chapter_exe）」と「構成推測（JLスクリプト）」の2層分離と同じ構造上の課題を抱えている。JLSコミュニティは推測層を局別・番組別スクリプトで運用調整する方向で発展してきた。

# 1. パラメータ調整の実例（収集項目1）

## 1.1 主要パラメータの公式定義と既定値（JL_標準.txt本文より）

**事実**（出典: https://raw.githubusercontent.com/yobibi/join_logo_scp/master/JL/JL_標準.txt ）

- `logo_level 6` — 構成推測時のロゴ使用（1:なし 2-8:ロゴ情報使用、大きい程ロゴ情報優先）
- `logo_revise 23` — ロゴ使用関連の構成変更（0-4:ロゴ端の削除、+10:ロゴ内削除あり、+20:ロゴ外広域削除あり）
- `autocm_code 6` — ロゴなし時の15秒単位CM検出（0:なし 1-10:大きい程強く検出）、`autocm_sub 10`、`autocm_scope 40`（最後から指定秒以降の短時間構成は手前がCMなら継続）、`autocm_maxprd 60`（指定秒超は15秒単位でもCM扱いしない）、`use_autocmtr 1`（ロゴなし時の予告検出拡張）
- `param_adduc 0` — ロゴなし不明構成（0:制御なし 1:残す）
- `param_cuttr 0` — 予告等終了後のロゴ付き15秒単位構成（0:残す 1:カット）
- `param_cutsp 0` — 番組提供カット（0:残す 1:カット）※「誤検出の可能性から残すを推奨」とコメントあり
- `param_nosc 0` — シーンチェンジなし無音位置のCM判断（0:自動 1:使用しない 2:使用する）、`param_cntsc 0`（無音SC数が多い構成内の分離）
- `cuttr_code 2`（0:検出なし 1:CM明けから数える 2:CM明け／CM直前を自動 3:CM直前）、`cuttr_limit 1`、`use_addtr 1`（予告が見つからない時のロゴなし予告検出）
- `param_wlogo_trmax 00:02:10` — 予告番宣部分と認識する最大ロゴ期間
- `param_wcomp_trmax 00:01:10` — 予告番宣部分と認識する１構成あたり最大期間
- `param_wlogo_sftmrg 3.5` — ロゴ期間が通常より短い場合の延長補正最大期間
- `param_wlogo_summin 00:00:20` — ロゴ期間合計が指定期間未満ならロゴなし扱い
- `param_wlogo_lgmin 20.0` — 推測時のロゴ有情報確定と認識する期間
- `param_wlogo_cmmin 40.0` — 推測時のロゴ無情報確定と認識する期間
- `param_wlogo_revmin 125.0` — CM構成ではないロゴなし期間が不明構成と認識する最小期間
- `param_mgn_cmdetect 0.25` — CM構成で15秒単位ではない可能性と認識する誤差フレーム期間、`param_mgn_cmdivide 0.1` — CM構成内部の分割を許可する誤差フレーム期間
- `param_wcomp_first 30.0` / `param_wcomp_last 30.5` — 先頭/最後構成をロゴなし扱いする最大期間、`param_lgcut_first 12.0`（最初からロゴあり時の開始マージン最大期間）
- エンドカード認識（`addec_code1 31303` 等5優先度、5秒/3秒/10秒構成）、番組提供認識（`addsph_code*`, `addspt_code*`）の優先度コード体系
- JLSコマンドラインオプション: `-CutMrgIn/-CutMrgOut`（シーンチェンジ↔ロゴ端のフレーム数、「通常ロゴ別の固定値。指定した方が精度が上がります」「指定がない場合に自動検出する処理が入っています」）、`-CutMrgWI/-CutMrgWO`（ロゴ端にSCがある場合CutMrg値を使わない判断、2=自動判断）、`-lastcut`、`-set`（`-set base xxx` で開幕ロゴ扱い調整）等。出典: https://github.com/yobibi/join_logo_scp
- Amatsukazeプロファイル側（EncTools「私のAmatsukaze設定」より、実際の運用値）: 「出力する最短区間（秒）: 既定値 (5)」「PMT更新によるCM認識: 5:5」「ロゴ検出判定しきい値を低くする: No」「ロゴ検出に失敗しても処理を続行する: No」「CM解析でロゴを使用しない: No」「並列ロゴ解析: Yes」。出典: https://enctools.com/my-amatsukaze-settings/
- rigaya改造版 1.1.1.2: 「CMカット点を本編側へ指定フレーム数だけ補正する設定を追加」（例: オフセット5）。出典: https://rigaya34589.blog.fc2.com/?cat=33

## 1.2 局名・番組名つきの調整実例（変更前後と効果）

**事実**（各出典は文中に付す）

1. **BS日テレ「ゴルフサバイバル」** — 余計な場所がカットされていた。`JL_標準.txt` をコピーした `JL_標準 BS日テレ.txt` で `Default param_adduc 1`（ロゴなし不明構成を制御なし→残す）に変更し正常化。またCMカット不良時には `Default logo_level 7`（6⇒7）を試した。出典: https://vafee.blog.jp/archives/1080098377.html
2. **BS-TBS** — 専用 `JL_BS-TBS.txt`（logo_level=8）を運用。出典: https://vafee-lab.com/ubuntu/2026061808.html
3. **ダンジョン飯（BS11 / SBS）** — CM解析結果の「Mix」構成（3613〜45870フレーム、1410秒中ロゴ1376秒）にロゴなしCMが取り込まれ分割できない。`Default logo_level 8` でMixを分けられるが「30秒CMが29秒になって困ってる」。BS11は「解析に変化なし」、SBSでは詳細ログの通り変化（90秒L構成の最後30秒がCM、実ロゴ端は927/30044/30957/48752）。出典: https://mevius.5ch.io/test/read.cgi/avi/1701608228/ （CMカットスレ★7 レス55-58）
   - ※「SBS」の表記は投稿原文ママ。どの局を指すか本文では特定できない（静岡放送の可能性はあるが推測）。
4. **AT-X（送出遅延）** — 「先週よりAT-Xがコンテンツ送出を1秒程度遅らせてきました。JL_ATX.txtによるCMカット精度が悪化した方は、`Default autobase 00:00:31` にすれば、ある程度改善できます」。別ユーザーは `Default autobase 00:00:32`＋開始位置検出の追加（`Find S 22.0/20.0/17.0/15.0 … -SMA 0.0 …+$len_headmute`、`Force S …`）で「先頭に無音・暗転画面が入る量が減りました」。出典: https://jbbs.shitaraba.net/bbs/read.cgi/computer/44736/1562757840/ （その2 レス613-616）
5. **SBSの30秒CMが29秒化** — `AutoDel S -30.0 -Nlogo 2 -force` でも切れず、「AutoDelの位置検索範囲はデフォルト1.2秒なので、30秒では29秒弱（28.7秒）の所が対象になる」。最終的に `AutoDel S -31.0 -Nlogo 2 -force`（31秒）で対応。誤差調整は `-Dm 0.1`（-Dmargin）。他の候補として `Default logo_revise 24`、`Default param_wlogo_cmmin 20.0`、chapter_exeの`-e`（無音前後検索拡張）が挙げられた（動作未確認と明記）。出典: https://mevius.5ch.io/test/read.cgi/avi/1701608228/ （レス63-68）
6. **ロゴなし45秒Trailer（最弱テイマー、BS朝日）** — バンテリン1分CMの後半45秒がロゴなしでTrailer(add)扱い。AutoDelでも切れない→「AutoDelでロゴなしを無理やりカットする場合は `-final` が必要」。15秒+45秒を「1分CM」として結合するJL例（`MemSet AUTO -order 30 { AutoDel 60.0 -Dm 0.25 -fromC -ZoneN -Fmid 2.0 2.0 -underC 2 -AC 15.0 }`）も提示された。出典: 同上（レス109-111）
7. **AT-Xの24分最近傍カット** — 「at-xのcmカットがやはりいまいち。cm解析で得られた各区切りから一番24分に近い幅になる区切りのtrimを作る」要求に対し、`MemSet mbase_main_start { Find E 00:24:00 00:23:00 00:30:00 -fromlast }; Call "JL_ATX.txt"` の4行JLスクリプトで実現（Findを先に挿入するとそちらが優先される）。出典: https://mevius.5ch.net/test/read.cgi/avi/1752302318/ （その8 レス946-948）
8. **ネクロノミ子のコズミックホラーショウ（BS日テレ）** — 本編内に右下スポンサー提供が表示され局ロゴが消えている期間がCM判定されカットされる。同じ構成のBS日テレ番組が(add)判定で残る例とログ比較により、原因は`Default param_cutsp 1`（番組提供カット）の誤検出と判明。対策として「短いロゴ抜け期間は残す」JL1行: `AutoIns E -Nauto 1..-2 -EndNextL -fix -LenN 1.0 11.0`（11秒以内のロゴ抜け構成は残す。要rigaya版AmatsukazeまたはCMカットスレ配布の新JLS）。出典: https://mevius.5ch.net/test/read.cgi/avi/1752302318/ （その8 レス44-53）
9. **番組提供カットの一般形** — 「JL_標準.txtをJL_標準提供カット.txtって名前でコピーして `Default param_cutsp 1` と修正して使う」（5ch その3 レス988）。出典: https://mevius.5ch.net/test/read.cgi/avi/1603846355/
10. **ロゴなし15秒構成が予告認識される誤検出** — `use_autocmtr 0`/`use_addtr 0`/フラグ`TPTRLIM0`等を試したが解消せず、後に「あまりにうまくいかないんでもう一度確認したらロゴありだった」と自己解決。この際、第三者から「Trailer(cut-cancel)は設定でカットできます（この設定を使っているJL_MBS.txtでも）: `Default param_cuttr 1 # 予告終了後のロゴ付き15秒単位構成（0:残す 1:カット）`」という情報提供あり。出典: https://mevius.5ch.io/test/read.cgi/avi/1701608228/ （レス122-124）
11. **ロゴ付き新番組番宣のみカット（シャングリラフロンティア21話、ぽんのみち8話）** — 「新番組のロゴ付き番宣だけをカットしたいが前後のLは残したい」→ `AutoDel 15.0 -fromTR -underC`（-fromTRはTrailer全般、-fromTRaはTrailer(add)のみ、-fromTRrはTrailer(add)以外）。JL_標準の後半に記述すれば機能、前半なら`-lazy`か`-final`が必要。JL_MBS.txtでも解決。出典: 同上（レス129-145）
12. **クレヨンしんちゃんのドラえもん告知15秒** — 「予告後の『テラサの告知5秒』と『ドラえもんの告知15秒』が回によって違う結果になり安定しない。ドラ告知15秒はL判定になることがある」。fTCB（最後の15秒未満1構成をカット＝実際は14秒以下カット）はまれに予告側を誤爆。対策コマンド: `AutoDel E -15.0 -Nauto -1 -AC -20.0`（-fix を付けると:L-Edge(cut)表示）。出典: 同上（レス164-168）
13. **AutoEdgeの上限は通算時間** — 「5秒から95秒の構成をカット」(`AutoEdge B -code 1005 -period 5 -maxprd 95`)が想定どおり動かず、「AutoEdgeの上限時間は通算時間になるので 35+10+15+90 で -maxprd は150以上、-scope も150以上が必要」と自己解決（`AutoEdge B -code 1005 -scope 200 -period 5 -maxprd 200`）。出典: 同上（レス49-51）
14. **冒頭の固定テロップ強制カット** — 時代劇冒頭の「不適切な～当時の時代背景云々」→「冒頭5秒の強制カットはフラグ追加(vHCF:5)で可能。AutoDelコマンドで記載する場合は5秒カットに-forceを追加」。出典: 同上（レス45-47）
15. **通販（夢グループ）対策** — 「ロゴ区間に120秒区切りがあれば全カット: `AutoDel S 120.0 -fromL -underC 1`」。ただし「本編で120秒区切りがあるとカットされる」「通販のLが90秒＋30秒みたいに認識された場合は対応しない（-underC 1を消せば跨ぎも消せるが誤爆率上がる）」。出典: 同上（レス48-74）
16. **番組ごとの振り分け運用** — hookAmatsukazeCLIや`JL/data/ChParamJL1.csv`（放送局別）＋`ChParamJL2.csv`（番組別）で「薬屋のひとりごと用」等の個別AutoDel/AutoEdgeを振り分け。`JL_ANYSEL`をAmatsukazeのJoinLogoScpコマンドファイルに指定すると両csvが自動読み込みされる。If文でのタイトル判定例も提示（`If ${file_title:Cm}>0`）。出典: 同上（レス32-38）、https://mevius.5ch.net/test/read.cgi/avi/1752302318/ （その8 レス3073-3091）
17. **スーパー！ドラマＴＶ「Dr. HOUSE 5」** — B/C/DパートCM明け冒頭5秒のジングル「海外ドラマはスーパー！ドラマTV」が残る判定。`call "JL_フラグ指定.txt"`＋`AutoDel S 5.0 -Nauto 2..-1`（CM明け冒頭の5秒を無音区切りある場合限定でカット）をJL/user/に置き、ChParamJL2.csvに`310,"Dr． HOUSE","SuperDramaTV.txt","",,,`と記載して解決（ドットは全角`Dr．`でないとマッチしない——記号は全角、英字は半角大文字変換される仕様）。出典: https://mevius.5ch.net/test/read.cgi/avi/1752302318/ （その8 レス314-324）
18. **東映チャンネルの番組前テロップ（ロゴなし17秒）** — L判定される。「番組前カットにロゴ情報が使えない時は、先頭からの位置指定でカットする方法が使えます。17秒区間あるなら正確に特定可能」→ `AutoDel -fromhead 1000 -Dm 600 -EndHead -RAC -17.0 -RAC 0 -noedge -keepC`。認識しない場合は`-RAC -17.0 -RAC 0`部分を無音シーンチェンジ情報（`-RSC -17.0`／`-RSMA -17.0 0`）に変更。出典: 同上（その8 レス426-432周辺）
19. **地上波30分番組の最後15秒CM残り** — PMT更新%の変更（1%→18%）ではカット判定に影響なし。解決JLスクリプト例: `[残った最後15秒をカットする] AutoDel E -15.0 -Nauto -1`（無音SC区切りなくてもカット: `-force`、最後18%内に制限: `-Ftail $MAXTIME*18/100`）、`[全体の最後18%区間を強制カット] AutoDel -fromAbs $MAXTIME-$MAXTIME*18/100 -endAbs $MAXTIME -force`。「番宣とかロゴがある所に特殊帯があったりCM背景が真っ白のものとか誤判定あるある」の言及あり。出典: 同上（その8 レス4447-4477）
20. **BSアニマックス** — JLparam_set1.csvでjoin_logo_scpオプション`-CutMrgIn`/`-CutMrgOut`を局別に固定値指定。出典: http://blog.livedoor.jp/fles/archives/74481532.html
21. **BS11・SBSのMix構成（ダンジョン飾）再掲** — 「`Default logo_level 8` でMixを分けられる」（上記3）。
22. **PMT更新の実運用値** — 「ググってヒットしたIssueでやり取りがあったので頭5%、末尾30%にしてます https://github.com/nekopanda/Amatsukaze/issues/6」（したらば その2 レス686）。EncToolsの実設定は「5:5」。出典: https://jbbs.shitaraba.net/bbs/read.cgi/computer/44736/1562757840/ 、https://enctools.com/my-amatsukaze-settings/
23. **ねほりんぱほりんの分離** — JL_NHK.txt使用時にMC喋り部分・本編・録画マージンが分離出力される件で、第三者が「カット設定の`param_adduc`（ロゴなし不明構成 0→1）と`param_nosc`（シーンチェンジなし無音位置のCM判断 0→1）を0から1に書き換えてやってみると何か変わりそう（憶測）」と提案。出典: https://jbbs.shitaraba.net/bbs/read.cgi/computer/44736/1562757840/ （その2 レス784-786）
24. **JLファイルの文字コード** — SJIS、またはBOM付きUTF-8/UTF-16でないと読み込まれない（BOM付きが重要）。出典: https://mevius.5ch.io/test/read.cgi/avi/1701608228/ （レス117-120）

**示唆**
- JLS系の調整は「局/番組単位の例外スクリプト」で破綻を吸収する運用が定石。依頼者のcm_rules相当層にも、(a)ロゴなし不明構成を残す/切るのスイッチ（param_adduc相当）、(b)ロゴ情報の重み（logo_level相当）、(c)15秒単位検出の強さ（autocm_code相当）の3軸を局別に露出させれば、コミュニティで実証された調整パターンをそのまま再現できる。
- 「30秒が29秒になる」現象（BS11/SBS例）は、境界検出の許容誤差（-Dm相当の位置検索範囲デフォルト1.2秒）と区画長の丸めが絡む既知の問題。依頼者の「境界ずれ6件」と同型と考えられる（推測）。

# 2. 局ごとJLスクリプト切替の実例と判断基準（収集項目2）

**事実**
- 標準添付の局別JLスクリプトと推奨局（EncTools「AmatsukazeのCMカットの精度を上げる」）:
  - `JL_ATX.txt`: AT-X
  - `JL_MBS.txt`: MBS、TBS、BS-TBS

# 3. 失敗事例と回避策（収集項目3）

## 3.1 ロゴ学習・ロゴ検出の失敗

**事実**
- rigaya氏による自動ロゴ解析（Amatsukaze改造版 1.0.7.0、2026-05-10）の失敗条件の明記:
  - 「ロゴ枠内の背景色がなるべく同じフレームが、複数の背景色パターンで得られる」とうまくいく。「アニメが特に取得が容易で、次に映画などがロゴがとりやすい」
  - 失敗する条件: 「枠内背景色が同じになるフレームがない」「背景色がずっと同じ色（映画のレターボックスとか）」「枠付近(特にロゴ直下)にテロップ枠や文字などの固定構造が出続ける」「ロゴっぽい別の何かが表示され続ける」
  - 「今回の自動ロゴ解析は一般的な右上ロゴしか見ていないので、右下や左上ロゴは引き続き手動」「残念ながら100%うまくいくわけではない」
  - 出典: https://rigaya34589.blog.fc2.com/?cat=33 （1.0.7.0記事）
- AT-Xのロゴ作成が「776エラー」でできない（その8 レス16-25）。AT-Xは「数秒しかロゴ出ない」。ショートアニメ一挙放送でロゴ生成はできるが「それを使ってロゴ消ししようとしてもロゴが見つかりません」。成功者の条件: 「・ロゴ背景に模様がないフレーム ・結合後のロゴ背景色は複数存在するように ・フェード部分はカットして入れない」（ロゴ期間のみts結合したものを使用）。通常のロゴ登録では消せず「プロファイルの詳細設定から追加ロゴ消し用ロゴリストに登録したらできた」。出典: https://mevius.5ch.net/test/read.cgi/avi/1752302318/
- WOWOWプラス（旧シネフィルWOWOW）は「真っ暗背景、CMスタートだから取りにくい」のか、いくらロゴ生成しても `Logoscan.hpp:1034 Message: Insufficient logo frames`（ロゴのサンプルが少ない警告）。しきい値やスキャン数を弄っても解決せず、AviUtlのlgdを入れても認識しない（その3 レス付近）。出典: https://mevius.5ch.net/test/read.cgi/avi/1603846355/
- 「昔の4:3放送で黒帯が有るやつ（時代劇）とか、放送大学みたいに講師が映しっぱなしで絵面変わらんやつは解析の失敗率高い」「なるべく16:9や動きがそこそこあるのをわざわざ録画してロゴ切り抜きしてる」（その3）。出典: 同上
- 「どの番組でも（ロゴ消しが失敗する）という共通点を考えると、CMや番宣中のなにかをロゴとして認識しちゃってて そこの横線？が混ざっちゃってるのかもね。TSスプリッターかMurdocCutterで本編だけ切り取って解析回せば良いかもしれず」「番組テロップとロゴがずっと重なってる様な番組でロゴ解析したら 流石に番組テロップを薄く抜いた感じのロゴが出来上がった事が有る」（その3）。出典: 同上
- バラエティのロゴ解析失敗: 「TBSのバラエティとかなんだけど、ロゴ解析しても素材足りなかったりでCMカットできぬ…ロゴに番組のテロップが掛かってるとなりやすいのかな」「バラエティもので終始ロゴに特殊マークが被っている番組のはロゴ解析失敗するね。仕方ないのでチャンネル設定でロゴ無しを追加してウォーターマーク消しは諦めてる。ただ無音判定とかでCM切り分けしてるので誤判定起きていないかエンコ後の確認は必要」（したらば その2 レス766-769）。出典: https://jbbs.shitaraba.net/bbs/read.cgi/computer/44736/1562757840/
- 「その局ロゴの所に、『○○特集』みたいな輝度MAXで縁取りされた黒文字番組アイコンが入ってるとミスる。最近のNHKの番組でもあったし、意図的な自動cmカット潰しかもしれん」（したらば その2 レス769）。出典: 同上
- 黒背景・黒帯ロゴ: 「黒枠4:3でロゴが常に黒背景のソースだとロゴ検出できない時がある」「局ロゴが黒帯の上にある場合エラーが出て解析できない」→「同じ局で黒帯無い番組を録画してロゴスキャンして対応してる」（したらば その2 レス397-398, 919-920）。出典: 同上
- ロゴ消し品質: 「ロゴ消し、数十回に1度の割合で注意して見なくても分かる程度に跡が残る（BS11の例）」→「うまく消えないときはそのソースでロゴ解析をやり直すときれいに消えるのが採れるよ～」「適当に実写から取得したロゴとアニメから上手に取得したロゴならアニメの方を選んでくれる感じ。ノイズだらけのロゴがたくさんあっても、低ビットレートやノイズが多い動画で誤認識する元だから、きれいに消えないロゴは除外しよう。解析も早くなるしね!」（したらば その2 レス469-477）。出典: 同上
- 新旧ロゴ併存: 「新旧局ロゴなら期間設定するのがベスト。どうしても期間がわからなければ全部有効にチェック入れれば自動判定してくれる。局ロゴは複数有効にチェックが入っていれば、全部判定して一番いい数値のロゴを使ってますよ。SD/HDでロゴの位置が変わるCSの局などはこちらで対応。チェックに有効ロゴ数分の時間かかるけど」（したらば その2 レス139-146）。出典: 同上
- Amatsukaze黎明期（2018）: 「Amatsukazeで採取したロゴの精度が低い」→作者「ロゴ解析の精度が悪いのはロゴの精度が悪いんじゃなくて、amatsukaze側実装の問題。今精度上げてるから待って」→「ロゴ解析の精度上げた。うまくいかないところとかあったら教えて」。外部lgdの直接取り込みは長らく不可（「そもそも*.lgdファイルへの変換さえまともにできてないから逆変換も作る気ない」）。ただしrigaya改造版1.0.4.4（2025-12-29）で「チャンネル設定のロゴファイル欄にlgdファイルをドラッグドロップして追加できるように。AviUtlのlgd形式も追加可能（ただし拡張領域を無理やり補うので精度は低いかも）」。出典: https://jbbs.shitaraba.net/bbs/read.cgi/computer/44736/1530904083/ 、https://rigaya34589.blog.fc2.com/?cat=33 （1.0.4.4記事）
- 現代版の自動ロゴ生成: rigaya改造版の「ロゴ自動解析処理」（1.0.7.0）、「自動ロゴ検出機能の精度を少し改善」（1.0.8.2、2026-07-14）、「ロゴ検出の高速化」（1.1.1.4、2026-10-31）、AmatsukazeGenLogo（CLI、AviUtl形式lgdも出力可）。出典: https://rigaya34589.blog.fc2.com/?cat=33 、https://enctools.com/amatsukaze-aviutl-logo/
- logoframe後継実装（tobitti0版）の自動LGD生成: 「初回は右上の領域から永続的に現れる輪郭を探し、ロゴを含む矩形を決定。矩形外周の背景がほぼ単色になっているフレームから仮LGDを作り、仮ロゴとの一致度が高いフレームだけでLGDを再構築」「一致率が-logo-matchを下回ると次の世代を生成し、同じ動画を再解析。新世代は改善した場合だけ最新版に昇格し、改善しなければ従来世代へ戻す」「生成対象には、ロゴが十分な強さで表示され、ロゴ背後の映像も変化する範囲が必要。短い同一シーンだけを指定すると背景サンプルが偏る」。オプション: `-logo-samples 600`、`-logo-bg-threshold 12`（単色背景と判断する輝度差）、`-logo-edge-threshold 40`（永続輪郭を調べる輝度差）、`-logo-match 10`（新世代生成の一致率下限%）。出典: https://github.com/tobitti0/logoframe
- 掲示板での要望: 「チャプター作成アプリに動画のロゴ検出機能を追加した。思ったよりうまくロゴのあるフレームを検出出来ている（こともある）」（CMカットスレ★7 レス87）、「ロゴ検出を隙間時間でやってる。…逆変換でやったけどいまいち、応用したパターンマッチもいまいち。それで今エッジ検出やってるけどこれは調整に時間がかかる可能性」（同レス82）。出典: https://mevius.5ch.io/test/read.cgi/avi/1701608228/
- 「ロゴ消ししない（オフ）にしてもロゴ検出とchapter_exeを実行しやがる。どこかに設定項目があってオフにできるのか？」（その8 レス974、回答は確認できず不明）。出典: https://mevius.5ch.net/test/read.cgi/avi/1752302318/

**示唆**
- 依頼者の問題1（ロゴ学習が空・壁・走査線のような安定画を誤拾い）は、JLS系でも「ロゴっぽい別の何かが表示され続ける」「背景がずっと同じ色」として同型に認識されている。コミュニティの回避策は (a)背景複数色×無模様フレームの選別、(b)フェード区間を学習から除外、(c)学習素材を「動きがある16:9」に限定、(d)一致率しきい値での再生成・世代管理（tobitti0方式）、(e)複数ロゴ候補を保持してスコア最大を選択、(f)期間指定による新旧ロゴ分離、の6パターン。依頼者が「直近で学習時/照合時のロゴらしさ判定を共通化して改善済み」と述べている点は (a)+(d) 方向と一致する（推測）。
- 依頼者の常時3局運用でロゴキャッシュが不安定、という点に対し、コミュニティの知見は「局ロゴは複数有効なら全部判定して一番いい数値のロゴを使う」＋「きれいに消えないロゴは除外」（負の候補排除）であり、キャッシュを単一最新版にせず「候補集合＋スコア選択」にする構造が経験上有効とされている（推測を含む示唆）。

# 4. PMT更新によるCM認識の実態（収集項目4）

**事実**
- 起源: nekopanda/Amatsukaze Issue #6「WOWOWで本編のみ分離ができないことがある」（2018-07-29、supertoppo7）。WOWOWの前後カット不能なログ（PMT更新 0分6.21秒/43分41.19秒/55分6.20秒）を提示し、「冒頭と最後の指定秒数か分数以下でPMT更新がある場合は、カットできるオプションをプロファイルで指定できると助かる。PMT更新が複数回生じる番組がある」 と要望。作者の実装後、要望者は「PMT更新かつシーンチェンジがあるときのみ、対象にしてくださっているのですね。誤爆もなさそうですね」と確認してクローズ。出典: https://github.com/nekopanda/Amatsukaze/issues/6
- 仕組み（EncTools解説）: 「番組の前後にCMが残ってしまう場合に効果的」。「最初から□%と最後から□%にPMT更新がある場合はCMとする」の%は「カットしたい長さ÷動画の長さ×100」で求める。例: 31分録画・前後マージン30秒 → 0.5÷31×100=1.61→2%。後3.5分なら11.29→12%。「もちろんPMT更新がなければカットされません。PMT更新があるかどうかはログを見ればわかる」（`[PMT更新] ストリーム時刻: …` の行）。出典: https://enctools.com/amatsukaze-cm-cut/
- 「TSのPMT更新を利用することもでき、番組の前後のCMを確実にカットしてくれます」（EncToolsメリット記事）。出典: https://enctools.com/amatsukaze-merit/
- 実運用値: 「頭5%、末尾30%」（したらば その2 レス686、Issue #6由来と明記）／「5:5」（EncTools 私の設定）／「2%1%」（WOWOWプレミアムシネマ運用、その8）。出典: https://jbbs.shitaraba.net/bbs/read.cgi/computer/44736/1562757840/ 、https://enctools.com/my-amatsukaze-settings/ 、https://mevius.5ch.net/test/read.cgi/avi/1752302318/
- 失敗例・限界:
  - 「NHKのBSはPMT更新で誤カットされることがたまにある」（その3 レス515）
  - 「シーンチェンジ情報がないときにPMT更新CM認識を有効にしているとエラー終了する問題を修正」（rigaya改造版 1.0.6.5、2026-04-17）——PMT更新CM認識がシーンチェンジ解析に依存していることの傍証。出典: https://rigaya34589.blog.fc2.com/?cat=33
  - 「CSやローカルでよくあるロゴ出っぱなしで次の番組に移行する部分がうまくカットできない。PMTを設定してもうまく検出とカットがされない」（その8）
  - 「地上波30分番組の最後15秒のCMだけ残ってしまい、PMT更新%を変えても影響なし」（その8 レス4447）
  - 出典: https://mevius.5ch.net/test/read.cgi/avi/1603846355/ 、https://mevius.5ch.net/test/read.cgi/avi/1752302318/

# 9. 依頼者への統合示唆（要約）

1. **ロゴ学習（問題1）**: 失敗条件のコミュニティ通説は「背景単色」「固定構造の重なり」「ロゴに似た安定画」で、依頼者の誤拾い現象と同型。実効性が報告されている対策は (a)学習フレームの選別条件（背景複数色・無模様・フェード除外）、(b)一致率しきい値による再学習と世代管理（tobitti0方式）、(c)複数ロゴ候補のスコア選択、(d)期間指定による新旧ロゴ分離、(e)学習素材を「動きのある16:9」に限定、の5点。
2. **ロゴなし経路（問題2）**: コミュニティの結論は「多少落ちる」「誤判定は事後確認前提」。本編中のCM判定主役ではなく、JL_ATX型（前後カット＋強い時間制約＋長時間無音＋分割）への役割限定が実績ある。依頼者のcm_scenarioの38%誤提案はこの構造的限界と整合的。
3. **番宣誤認（問題3）**: コミュニティも内容判別を諦めており、位置（先頭/末尾/CM明け）×構成長（15秒単位）×ロゴ有無×時間制約×番組名マッチで対処している。依頼者の「始端が早い」問題への有望方向は、CM区間先頭の番宣区画を位置ベースで剥がす規則と、TSイベント（PMT更新・音声構成変更）による前後確定（AmatsukazeのPMT更新機能がまさにこの設計）。
4. **相補経路（問題4）**: 「ロゴあり経路」と「ロゴなし経路」の局別使い分け（NHK/AT-X/WOWOW=ロゴなし寄り、MBS/TBS系=ロゴ重視、BS-TBS=logo_level 8等）が実運用の標準形。依頼者の「同一録画で双方が別の正しいCM区間を検出した」観察は、この局別併用思想の延長として、局単位でどちらの経路を主に使うか決める表（運用マトリクス）に落とし込める（推測を含む）。
5. **BS11**: 暗転区切りによるSC欠落が構造的原因。ロゴ経路・ロゴなし経路双方の境界精度上限に関わるため、BS11だけ「時間的制約（30分枠×24分最近傍）」等の代替確定手段を併用する運用が合理的（推測を含む）。
6. **処理量**: 「録画番組のエンコードのボトルネックは完全にCM解析」という現在時点の利用者認識があり、高速化(並列ロゴ解析、CM解析のスキップ)と精度改善の両輪がコミュニティの関心である。
