# DT295 の内蔵カードリーダーを外部デスクランブルに使えるか

2026-11-20。段2（外部複合）に進む前提として、「内蔵カードリーダーを
PC/SC のリーダーとして使う」ことが可能かを突き詰めた記録。

結論を先に書く。**純正ファームウェアのままで内蔵カードを外部から読むのは
構造的に不可能**で、可能にするには**ファームウェアを差し替える（段3・段4）**しかない。
差し替えれば可能である根拠も実測・文書で揃っている。

## 1. なぜ今は使えないか（構造）

3つの壁があり、どれも独立している。

### 壁1: USB からは読めない（クラスが違う）

実機で確認した DT295 の USB 構成:

- インターフェースは **1本だけ**、クラスは **`ff`（ベンダ固有）**
- エンドポイントは 9 本（`0x02`/`0x07` = Bulk OUT、`0x81`/`0x84` = TS の Bulk IN、
  `0x83` = Interrupt IN、ほか）
- **CCID（`0x0B`）ではない**

イメージに入っている PC/SC ドライバは `ifd-ccid.bundle` だけなので、`pcscd` は
この機器をリーダーとして認識しない。実機で確かめた結果:

```
card0 list readers failed: Cannot find a smart card reader.
ERROR stage=card_init
```

`pcscd` → `bcasd` → `cardrelay` → `torne-b25` の鎖は全部正しく動いていて、
**最後の「リーダー」だけが無い**。

### 壁2: カードはファームウェアの内側にある

今の複合は `pix-ts-legacy` がファームウェアから `ts_key`（16バイト）を受け取って
自分で復号している（`dt295.c:1582`, `dt295.c:1885`）。B-CAS の APDU（`90 30`/`90 34`）は
**ホストから一度も送られていない**。

`vendor/pix-userland` が使っているカード関連のコマンドは次の2つだけ:

| コマンド | 用途 | 根拠 |
|---|---|---|
| `0x0a` | カードセッションの第1段・第2段 | `dt295.c:894,915` |
| （読み出し） | `0x0822AC` の状態4ビット | `dt295.c:832,860` |

つまり `pix-userland` は「カードが挿さっているか」と「セッションが張れたか」しか
見ておらず、**カードとの APDU のやり取りは実装していない**。

### 壁3: 純正ファームは生の複合前 TS を出さない

これは外部複合そのものの前提を壊す事実で、コミュニティの文書に明記がある
（`smpn2/pix-dt295` の `docs/device.md` / `docs/raw-ts.md`）:

> 生のスクランブルされた TS を取り出す経路は無い。出てくるのはカードで復号済みの TS
> （デスクランブルを切れば、無料放送 + PSI + データ）。

純正ファーム（System1）は**カードで復号した後の TS**しか出さない。したがって
「生 TS を出して外で複合する」という段2の構想は、**純正ファームのままでは
原理的に成立しない**。今出ているのは実は「リンク暗号（AES-128）を解いた後の
クリア TS」である。

## 2. では差し替えれば使えるのか（できる見込み）

**使える。** 根拠は3つ揃っている。

### 根拠1: ファームウェアに B-CAS の口がある

`smpn2/pix-dt295` の `docs/device.md` に、チップのコマンドとして明記されている。

| 項目 | 中身 |
|---|---|
| B-CAS のコマンド | **cmd 10 と cmd 11**（doorbell は `0xB9` = ch1） |
| パラメーターの置き場 | `0x08219C` と `0x081110` に **272 バイト** |
| 状態変化（抜き挿し） | `0x090074` の **bit `0x0200`**、メッセージは `0x0822AC` の 274 バイト |
| 応答 | `0x090074` の **bit `0x0400`**、274 バイト |
| ACK | 成功なら `0x0A00`（上位がコマンド種別のエコー、下位 0 が受理、`0x80` は拒否） |

出典: https://github.com/smpn2/pix-dt295/blob/main/docs/device.md の「コマンド
(doorbell 0xB8 / 0xB9)」の表（実機で確認済みと明記されている）。

**これは純正ファームの外から、チップのコマンドとして叩ける。**

### 根拠1-b: raw-TS 経路は Linux で実運用されている

`smpn2/pix-dt295` の `docs/raw-ts.md` は、純正ファームを使わずホストから cold で
チップを起こし、**スクランブルされたままの TS を配信する**経路を Linux で動かしている。

- Linux の mirakc のパイプラインで、`decoded: false` + 外部の `b25` フィルタで解除
- EPGStation からの録画とブラウザ視聴まで、純正ファーム無しで実機確認済み
- チップのリングは 4 MiB、pump を約 2ms ごとに回す

**ただしこの文書は、解除に「PC/SC リーダーの契約済みカードと pcscd」が要ると明記している。**
つまり raw-TS 経路そのものはカードを外に出す機能を持たない（カードはデバイス外の
リーダーにある前提）。DT295 の内蔵カードを使うなら、別途それを PC/SC で見せる必要がある。

### 根拠2: 別プロジェクトが同じチップで実装済み（内蔵カードを PC/SC 化）

MB8AC031-CFW（段3・段4 で導入予定）は、まさにこの口を使って
**カードを PC/SC のリーダーとして見せている**（`docs/card.md`）。PIX-DT295 で実測済みで、
ATR・T=1 の1往復・抜き挿し検出（`CARD_EVENT` bit10）まで動くと書かれている。

### 根拠3: 実機のハードは既に揃っている

- DT295 は 1台で、1本のベンダ固有インターフェース上に制御の口を持っている
- カードの抜き挿しは今のファームでも状態として見える（`0x0822AC` の上位4ビット）
- PC/SC の鎖（`pcscd`/`bcasd`/`cardrelay`/`torne-b25`）は全部入っていて動作確認済み

## 3. 差し替えで何が変わるか（正直な代償）

| 項目 | 今（純正ファーム） | 差し替え後 |
|---|---|---|
| 生の複合前 TS | 出せない | **出せる** |
| 複合の場所 | チップの内側 | **ホスト（torne-b25）** |
| 内蔵カードの使い方 | ファームが内部で使用 | **PC/SC リーダーとして外部から使用** |
| 選局 | `pix-ts-legacy` が I2C で実施 | **ホストが `I2CXFER` で実施**（作り直し） |
| ファーム状態機械（`0x11` 等） | 依存している | **依存が消える** |
| 復帰 | `dt295_recover`（USB 切り直し） | 状態機械が無いので**不要になる見込み** |

**代償**: 選局の実装を作り直す必要がある。今の `pix-userland` の I2C 列は
純正ファームの前提なので、CFW の `fe_dt295.h` の列に置き換えることになる。

## 4. 選択肢の比較

| 案 | 内蔵カード | 生 TS | 工数 | リスク |
|---|---|---|---|---|
| A. 純正ファーム + 内蔵カードを PC/SC 化 | **不可** | 不要 | — | 構造的に不可能 |
| B. 純正ファーム + 外付けリーダー | 使わない | 出せない | 小 | **外部複合が成立しない**（生 TS が出ない） |
| C. 純正ファーム + リモートカード | 使わない | 出せない | 小 | 同上。今も内蔵複合のまま |
| D. **CFW 差し替え + 内蔵カードを PC/SC 化** | **可能** | **出せる** | 大 | 選局の作り直し、実機確認 |

**B と C は「カードだけ外に出しても、生 TS が出ないので外で複合できない」。**
外部複合にしたいなら、D しか道が無い。

## 5. 勧める進め方

1. **段3（CFW 導入）を先にやる。** 生 TS が取れることを実機で確かめる。
   これが外部複合の大前提で、今の段2はこれ無しでは意味を持たない。
2. **段4（内蔵カードの PC/SC 化）を続けてやる。** 段3 でファームが変わっていれば、
   `docs/card.md` の口（`0x50`〜`0x57` または ARM 経路）がそのまま使える。
3. その上で段2（`torne-b25` を挟む）を最後に置く。

**設計書の段の順序を 3 → 4 → 2 に組み替えるべき**、というのがこの調査の結論。

- 選局の I2C 列を作り直すコスト（`fe_dt295.h` の列をホストへ移植する量）
