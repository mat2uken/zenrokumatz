# リポジトリ整理計画（2026-11-23）

この計画は、X96MaxLinuxTSEnc に分散したソース・作業記録・外部参照を整理し、参照先を一つに定める作業を示す。調査で確かめた事実と作業順を記し、ファイル移動・削除・Git 操作は含まない。実行は方針の承認後に着手する。

## 課題

### 再現性

`package/siano-ts/siano-ts.mk` は Git 除外下の `work/sources/siano-userland` を直接ビルドする。ローカル変更もパッチではなくスナップショットへ直接加えてある。このためクリーンチェックアウトではビルドできない。

コーデックの G12A 対応について、`sources.lock.json` と README は `vendor/meson-sm1-codecs/venc-h264/` を指す。実際のビルドは `package/meson-venc/patches/` の19個のパッチを当てる。正しい置き場所が示されていない。

### 現在の結論と古い結論の混在

`README.md` は11月10日時点の記述で、チューナー受信と SoC エンコードが未検証と書かれている。しかし 2代目の完成記録と11月22日の検証記録では、3台が録画と CM カットまで稼働している。

USB PHY の解釈は旧文書と新記録で異なる。1800秒分割についても、維持すると書いた文書と、廃止済みとして書いた文書が併存する。旧文書に解決の記述が無いため、誤読の原因になる。

### 索引と所在

`docs/` に全体索引が無い。`docs/aegis/INDEX.md` は6件を掲載していない。孤立しているドキュメントが2件あり、3代目の結論は `docs/aegis/work/` の中にしか無い。`docs/aegis/` の `adr/`、`baseline/`、`specs/` は空である。

### 証拠と重複

Aegis の過程記録は Git 除外下の `work/` にあるマシン固有パスを多数リンクする。clone しても根拠ファイルが存在しない。ブートペイロードは3箇所にほぼ同じものが置かれ、`work/` には同一内容のファイル4グループと0バイトのファイル20件がある。`artifacts/` の U-Boot 環境2ファイルも同一内容である。

### 未コミットの作業

本リポジトリでは、`docs/` の未追跡17件と修正6件、`prompts/` の未追跡3件に加え、ツールとコードの変更が残る。dtv_android では `experiments/cm-generic/` の8ファイルに465行の追加と43行の削除があり、`nas_src/README.md` が未追跡である。

出典: 各リポジトリの `git status --short`、`docs/` と `work/` の横断検索、`artifacts/` の MD5 比較。

## 整理の方針

ファイルを次の3層に分け、置き場所を固定する。

| 層 | 置くもの | 管理方法 |
|---|---|---|
| 追跡ソース | 自前コード・ビルド設定・現在の結論 | Git で管理する |
| 参照固定 | 外部由来のスナップショット | `vendor/` と lock に記録する |
| 生成物 | イメージ・ログ・キャッシュ | Git から除外し要約を残す |

判断のルールは次の四つである。ビルド入力になるファイルは追跡し、生成物は追跡しない。外部由来のソースは commit または SHA を lock に載せ、スナップショットは `vendor/` に置く。結論はトピックごとに一つだけ現行とし、古い文書には `SUPERSEDED` を付ける。証拠は要約と SHA を `docs/` に移し、元ファイルは `work/` に残す。

## 実施順

1. **段階0（現状保全）** 本リポジトリの未追跡17件と修正6件、dtv_android の8ファイルをコミットまたは退避する。両リポジトリの HEAD と差分一覧を記録する。未コミット作業を失わないことを完了条件とする。
2. **段階1（再現性の確保）** `sources.lock.json` に cfw、siano-userland、ファームウェア、dtv_android の現在の HEAD を追記する。siano-userland を `vendor/` へ移すか、tarball と SHA による取得へ切り替える。コーデック変更の置き場所を一つに決める。クリーンチェックアウトからのビルド成功を完了条件とする。
3. **段階2（構造の定義）** `docs/README.md` を新設し、トピックごとの現行文書への導線を作る。古い結論に `SUPERSEDED` を付け、孤立した2件を索引に載せる。3代目の結論をトップレベルへ移す。主要トピックが一箇所で辿れることを完了条件とする。
4. **段階3（作業記録の整理）** `work/` を日付付きディレクトリへ集約し、0バイト20件と同一4グループを除く。ブートペイロードは一箇所に置く。証拠の要約と SHA を `docs/` の検証索引へ移す。ドキュメントから Git 除外下の絶対パス参照が消えることを完了条件とする。
5. **段階4（外部との境界）** dtv_android の扱いを決定し、57箇所の参照のうち絶対パスを持つものを更新する。NAS の正ソースを Git 管理に加え、配備スクリプトのビルド元を `nas/src/` へ切り替える。配備元が正ソースを指すことを完了条件とする。
6. **段階5（入口の更新）** `README.md` を3台構成、RAM 起動、CFW、CM、EPG 廃止、検証状況に合わせて更新する。日付は着手日、追記には文書先頭の状態表示という規則を定着させる。README の記述が現状と一致することを完了条件とする。

段階0は他の段階の前提である。段階1と段階2は並行できるが、段階3は段階2の索引に依存する。段階4は段階0の確定後に着手する。
